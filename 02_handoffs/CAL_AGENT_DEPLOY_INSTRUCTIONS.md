## 2. Credentials — add to `/opt/alex-bot/.env`

```
GEO_CAL_CLIENT_ID=<same as GBP_CLIENT_ID>
GEO_CAL_CLIENT_SECRET=<same as GBP_CLIENT_SECRET>
GEO_CAL_REFRESH_TOKEN=<new — see below>
GEO_CAL_CALENDAR_ID=admin@geocarpentry.com
```

To mint `GEO_CAL_REFRESH_TOKEN` (per Cowork's handoff, unchanged):
1. Google Cloud Console → project `investoros-agents` → enable **Google Calendar API**.
2. OAuth Playground (https://developers.google.com/oauthplayground) → gear icon → "Use your
   own OAuth credentials" → paste the existing `GBP_CLIENT_ID` / `GBP_CLIENT_SECRET`.
3. Step 1: scope `https://www.googleapis.com/auth/calendar.events` → authorize as
   `admin@geocarpentry.com`.
4. Step 2: "Exchange authorization code for tokens" → copy the **Refresh Token** into
   `GEO_CAL_REFRESH_TOKEN` above.

Optional (already used by other agents, reuse if set): `TELEGRAM_BOT_TOKEN`,
`TELEGRAM_CHAT_ID` — Cal posts a Telegram warning if a lead's appointment falls outside
Mon/Wed/Thu 4-6pm CT instead of silently skipping it.

## 4. Cron — every 15 minutes, all day

```
*/15 * * * * cd /opt/agents/cal && /usr/bin/node cal.mjs >> /var/log/cal.log 2>&1
```

If the VPS doesn't already export `/opt/alex-bot/.env` into the environment for other agents'
cron entries, source it first (match whatever the other agents' crontab lines already do —
if they don't need this, `cal` doesn't either):

```
*/15 * * * * cd /opt/agents/cal && set -a && . /opt/alex-bot/.env && set +a && /usr/bin/node cal.mjs >> /var/log/cal.log 2>&1
```

## 5. Before leaving it unattended

1. Confirm the Airtable field names (section above) once the billing block clears.
2. Run it once by hand against a single test lead (`Lead Status = Appointment Set`,
   `Appointment Date` inside the Mon/Wed/Thu 4-6pm CT window) and confirm:
   - the event appears on `admin@geocarpentry.com`'s calendar with the right time/timezone
   - the lead's `Notes` field now contains `[GEO_CAL_SYNCED:...]`
   - running it a second time does **not** create a duplicate event
3. Also test one lead with an out-of-window `Appointment Date` and confirm it's skipped (and
   the Telegram alert fires, if configured) rather than creating a bad event.
4. Only then enable the cron.
