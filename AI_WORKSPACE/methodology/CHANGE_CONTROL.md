# Geo Carpentry AI Change Control

## Autonomous execution rule

Continue all safe, in-scope work without waiting for unnecessary acknowledgements. Ask Jorge only for a credential, irreversible external action, material business decision, or a fact that cannot be discovered safely.

## Required workflow

1. Read the current project memory and avoid repeating completed research.
2. Reproduce a bug or gather direct evidence before changing code.
3. Trace the data flow across every affected integration boundary.
4. State one root-cause hypothesis and test the smallest durable change.
5. Back up affected production files before deployment.
6. Add a regression test for the original failure or new safety requirement.
7. Verify syntax, the full automated suite, service health, logs, persistence, and the real user flow in proportion to risk.
8. Confirm that no unauthorized Calendar, Airtable, email, SMS, or WordPress action occurred.
9. Record the change, evidence, rollback location, limitations, and next work in sanitized memory.
10. Scan the public-safe backup for secrets and sensitive customer/business data.
11. Publish documentation to a separate GitHub branch and pull request; never merge automatically.

## Completion standard

A change is not complete because code was edited. Completion requires fresh evidence that the intended behavior works and that critical safeguards still hold. Avoid claiming absolute perfection; record unverified real-world scenarios plainly.
